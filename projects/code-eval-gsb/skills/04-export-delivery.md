# GSB 交付导出 · 追加记录到飞书多维表格

> 配置从 `../config.toml [feishu]` 读取（app_token / table_id），凭证在 `../secrets.toml [feishu]`（app_id / app_secret）。
> 脚本：`scripts/code-eval-gsb/append_delivery_feishu.py`（仅标准库，Python 3.11+）

每次 `analyze` 汇总完成、用户确认评价汇总表单后执行本技能：把表单内容映射为多维表格的一条记录，追加到交付飞书多维表格（`config.toml [feishu]` 指向的「数据表」）。

## 功能概述

1. 读取该题的 `-评价汇总.md`（必须是人工核对后的最终版）
2. 按交付表字段逐字段映射，生成记录 JSON
3. 调用 `append_delivery_feishu.py` 先 `--dry-run` 校验，再正式追加
4. 输出追加结果（record_id、留空字段清单），提示用户核对

**本技能不负责：**

- 生成或修改评价汇总表单（由 `03-summary-analysis.md` 完成）
- 替人工确认评分（表单中残留占位标记时中止）

## 命令

| 命令 | 说明 |
|------|------|
| export | 默认命令。评价汇总表单 → 追加一条记录到飞书多维表格 |

## 执行流程

**输入：**
```
项目名：<项目名>
类型：<类型>
提交人：<姓名>
TraeCN用户ID：<ID>
```

**步骤：**

1. **读取评价汇总表单**：
   `{work_root}/{session}/ai-model-result/<项目名>/<项目名>-{ALIAS}/<项目名>-{ALIAS}-评价汇总.md`

2. **完成度检查（不满足则中止）**：
   - 表单中不得残留 `【待用户填写】` / `【参考值，请确认】` 占位标记
   - 4 个模型的 SessionID（首轮）、交互轮次必须齐全
   - 4 个模型的「是否打断模型」必须齐全；选「有打断」的模型「打断分析反馈」必填
   - 3 组 GSB 结论、4 条「评价模型 XXX」必须齐全

3. **生成记录 JSON**：写入 `.tmp/<项目名>-{ALIAS}-delivery.json`，键名与多维表格字段名**逐字一致**，映射规则见下节。

4. **校验并追加**（在工作台根目录执行）：

   ```bash
   # 先 dry-run 校验字段名、选项值与留空情况
   .venv/Scripts/python scripts/code-eval-gsb/append_delivery_feishu.py \
     --json .tmp/<项目名>-{ALIAS}-delivery.json --dry-run

   # 确认无误后正式追加
   .venv/Scripts/python scripts/code-eval-gsb/append_delivery_feishu.py \
     --json .tmp/<项目名>-{ALIAS}-delivery.json
   ```

   - 脚本按「Repo URL」查重，重复时需用户确认后加 `--force`
   - 单选/多选字段的值必须是表格中已有选项；脚本会校验，不匹配时报错并列出全部合法选项
   - 「提交时间」「提交人」在飞书表中是**自动字段**（创建时间/创建人），脚本自动跳过；「业务领域」按约定留空

5. **输出结果**：追加的 record_id + 留空字段清单，提示用户在多维表格中抽查该条记录。

## 字段映射规则

### 基础信息

| 字段 | 来源 |
|----------|------|
| Prompt | 表单「Prompt」段的首轮提示词正文，**不含约束标签部分**（约束标签只进「指令约束（多选）」字段） |
| 提交时间 | 飞书自动字段（创建时间），脚本跳过 |
| 提交人 | 飞书自动字段（创建人，显示为应用名），脚本跳过；用户输入的提交人不再写入 |
| Repo URL | 表单「环境信息」 |
| Repo介绍 | 表单「环境信息」 |
| 任务类型 | 表单「题目标签」。单选已有选项：`Bug修复` / `0-1代码生成` / `feature迭代`（小写 f）/ `代码理解` / `代码重构` / `工程化` / `代码测试` |
| 业务领域 | 留空（除非用户明确提供）。单选已有选项：`纯后端API服务` / `Web前端` / `全栈Web应用` / `游戏开发（含UI渲染）` / `数据分析与可视化` / `3D/交互可视化` / `AI/ML应用` / `科学计算` / `命令行工具` / `桌面应用（含GUI）` / `自动化与工具脚本` |
| 修改范围 | 表单「题目标签」。单选：`单文件` / `模块内多文件` / `跨模块多文件` / `跨系统多模块` |
| 指令约束（多选） | 表单的约束标签列表，顿号连接。多选已有选项：`技术栈与依赖约束` / `架构或模式约束` / `代码风格与规范约束` / `非代码回复约束` / `业务逻辑约束` / `无约束` |
| 指令约束种类数（左边选了几个标签就填几个） | 单选字段，选项：`0个标签` / `1个标签` / `2个标签` / `3个标签` / `≥4个标签`；按实际注入的约束标签数选对应项，**不能填纯数字** |
| 操作系统 | 表单「题目标签」。单选：`MacOS/Linux` / `Windows` |
| 是否开启Max模式 | 表单「题目标签」的「是否开启 Max」。单选：`开启Max` / `未开启Max` |

### 模型区块（每模型一组字段，键名格式 `{字段} - {模型名}`）

⚠️ 交付表中模型区块按键名映射即可，与字段顺序无关；模型名以本期 `config.toml [[models]]` 为准（Odysseus / Athena / Poseidon / Cyclops）。

| 字段 | 来源（表单 item 段） |
|------|------|
| SessionID | 原文复制（交付表取**首轮** SessionID），禁止改写 |
| GithubPR | PR 链接 / N/A |
| 交互轮次 | 中文序数形式（一轮 / 二轮 / 三轮）；单选字段，若所需轮次数不在已有选项中，需先在表格里手动添加选项 |
| 交付完整性 / 指令遵循 / 任务规划 / 推理能力 / 执行能力 | 1-5（0825 期 5 个基础维度，数字字段） |
| 出现的问题(边界感) | 单选：`未出现边界感问题` / `出现了影响体验的越界问题` |
| 描述(边界感) | 可定位证据（轮次+动作）+ 对交付或过程的具体影响 |
| 出现的问题(长上下文) | 多选标签，顿号连接：`前文约束遗忘` / `已改代码回退/重复劳动` / `路径幻觉` / `lost-in-the-middle(遗漏中段)` / `前后自相矛盾` / `约束语义漂移` / `其他` / `未出现显著问题` |
| 描述(长上下文) | 可定位证据（轮次+动作）+ 对交付或效率的具体影响 |
| 出现的问题(思考) | 多选标签，顿号连接：`简单题过度思考` / `思考发散跑题` / `反复自我否定绕圈` / `思考不足直接猜` / `思考陷入死循环` / `其他` / `未出现显著问题` |
| 描述(思考) | 可定位证据（轮次+动作）+ 对交付或效率的具体影响 |
| 出现的问题(ToolCall) | 多选标签，顿号连接：`重复读取同一文件` / `文件间反复横跳` / `无效探索或无关调用` / `失败调用未能自行纠正` / `该用工具时不用/靠瞎猜` / `其他` / `未出现显著问题` |
| 描述(ToolCall) | 可定位证据（轮次+工具名称+动作）+ 对交付或效率的具体影响 |
| 是否打断模型 | 单选：打断填「有打断」，未打断填「无打断」 |
| 打断分析反馈 | 选「有打断」时必填：打断发生在第几轮、打断时模型在做什么、原因、能否按新指令恢复；无打断留空 |

> 0825 期 Add-on 维度改为「出现的问题 + 描述」字段组合（不再 1-5 打分），也**无「是否触发自动压缩 / context占用 / 长上下文 200K 阈值」字段**。Add-on 字段名带半角括号（如 `出现的问题(边界感)`），与「是否打断模型」等一起按 `{字段} - {模型名}` 拼接为完整键名。

### GSB 与评价

| 字段 | 来源 |
|----------|------|
| Athena和Odysseus谁更好 | GSB「Odysseus vs Athena」的胜出模型名。单选：`Athena` / `Odysseus` |
| Poseidon和Odysseus谁更好 | GSB「Odysseus vs Poseidon」的胜出模型名。单选：`Poseidon` / `Odysseus` |
| Cyclops和Odysseus谁更好 | GSB「Odysseus vs Cyclops」的胜出模型名。单选：`Cyclops` / `Odysseus` |
| 评价模型Odysseus / 评价模型Athena / 评价模型Poseidon / 评价模型Cyclops | 表单「评价模型」段，每题必填 4 条。固定格式：首行 Bad Pattern 概括（无则「无明显Bad Pattern 。」），随后按编号逐个对比其余每个模型（「N、与X对比：更好/差一点，理由」） |
| 其它信息 | 表单「其它信息备注」（含美观度，如有） |
| TraeCN用户ID | 用户输入 |

## 注意事项

1. **必须先 dry-run 再正式追加**；dry-run 输出的留空字段清单需人工过目，确认留空都是"本就无数据"而非漏映射。
2. 键名与字段名逐字一致（含空格、全角括号），脚本对未知键名直接报错。**本期字段名以实际 0825 交付飞书表为准**，若表头与本文档不一致，以脚本拉取到的表头为准。
3. 单选/多选字段只能写已有选项；如需新选项，先在多维表格中手动添加，再重新导出。
4. 多维表格是最终交付物，追加前确认表单已定稿；追加错误记录需在多维表格中手动删除后重新导出。
5. 所有评价文字已在 analyze 阶段经 humanizer-zh 处理，导出时**原文搬运，不得再改写**。
6. 首次使用前置：飞书开发者后台为应用开通 `bitable:app` 权限，并把应用添加为该多维表格的协作者。
