# 单批次标注协议（每批 15 条）

> **规则来源**：`docs/annotation-rules.md`（硬性规则，本协议的权威依据）  
> **原始底稿**：`docs/annotation-guidelines.md`（保持不动）  
> 本协议由 `skills/gsb-annotator/SKILL.md` 按批次调用，每次处理 ~15 条数据。

---

## 批次启动

- [ ] 确认本批次 Excel：`sessions/pairwise-gsb/<session>/<日期>/batch-<NN>/input/items_行{起}-{止}.xlsx`
- [ ] 图片已提取到：`sessions/pairwise-gsb/<session>/<日期>/batch-<NN>/images/`（命名为 `row_{原始行号}_{列名}.png`）
- [ ] `manifest.json` 已生成，知道每张图片对应行列和来源列
- [ ] 输出位置：`sessions/pairwise-gsb/<session>/<日期>/batch-<NN>/output/annotated_行{起}-{止}.xlsx`
- [ ] 疑难 case 记录位置：`sessions/pairwise-gsb/<session>/<日期>/difficult-cases.xlsx`

### 数据列说明

Excel 中有 4 列图片相关数据：

| 列 | 名称 | 内容 | 标注时的作用 |
|----|------|------|-------------|
| col4 | 输入图1 | 编辑前的原始图 | 一致性判断的基准 |
| col5 | 输入图2 | 参考图/风格图 | 参考生成的一致性基准 |
| col7 | 图片1 | 待标注生成图 A | 与图片2对比 |
| col8 | 图片2 | 待标注生成图 B | 与图片1对比 |

### 图片查看方式

标注时**必须按顺序查看**，不可跳过：

1. **先看输入图**（col4/col5，如有）：使用 `ReadMediaFile` 打开 `images/` 下对应 PNG，或查看 URL
2. **再看生成图**（col7/col8）：同上
3. **兜底**：任意图片无法查看时，**必须在 reason 开头注明“⚠️部分图片不可查看，仅基于prompt分析”**，并将该条**同时加入疑难 case 记录**，等待人工确认后再决定是否交付。

## 逐行标注协议（每条必过 9 步）

### Step 1：读 prompt，列约束清单

逐条列出每个硬约束，**保持要求必须单独列出**：

```text
主体：___
动作/姿态：___
数量：___
位置/空间关系：___
文字/文案：___
风格/色彩/滤镜：___
画幅/比例要求：___
保持要求（"保持XX""XX不变""保留XX""保持原比例"）：___
```

> ⚠️ 这一步决定后续所有判断质量。**保持要求漏列 = 一致性/指令遵循边界判错。**

### Step 2：判定任务类型

```text
输入图/参考图的列是否为空？
├── 是 → T2I（一致性维度填"不涉及"，一致性归因标签留空）
└── 否 → prompt 含什么关键词？
    ├── "编辑/修改/替换/去掉/加上/P成/纹" → 图片编辑
    └── "参考/风格/类似/仿照/根据...生成" → 参考生成
```

> **硬性规则**：T2I 任务**禁止**判断一致性或填写一致性归因标签。

### Step 3：查看图片 + 分别检查

**3a. 查看输入图（如有）** — 仅当 col4/col5 非空时执行

先 `ReadMediaFile` 打开输入图，确认：
- 输入图中有什么人物/物体/背景/风格？
- prompt 要求改什么？不改什么？（这是后续一致性判断的基准）

**3b. 查看生成图 图片1、图片2**

**3c. 指令遵循检查**（对照 Step 1 清单逐条问）

```text
对每个约束：
├── 完成了 → 过
├── 没完成 → 记下"哪个约束没完成、怎么没完成"
└── prompt 写了"保持XX"但这个对象没保持 → 🚨指令遵循，不是一致性！
```

**3d. 一致性检查**（仅编辑/参考任务，对照输入图 col4/col5）

```text
对比输入图和生成图，输入图中哪些内容 prompt 没说要改？
├── 人脸/身体特征变了？→ 一致性-人物保持差（真人/非真人分开）
├── IP 形象变了？→ 一致性-知名IP保持差
├── 风格/色调变了？→ 一致性-风格/色调保持差
├── 背景/道具等变了？→ 一致性-其他元素保持差
└── 都没变 → 过
```

**3e. 视觉效果检查**

```text
├── 结构：多手指/少手指/肢体错位/穿插粘连？→ 结构崩坏
├── 物理：悬浮/重力不对/反射异常？→ 违反物理规律
├── 自然：看起来假/不真实？→ 不自然（假）
├── AI感：真人场景有AI塑料感？→ AI感（⚠️输入图AI感强则豁免）
├── 画质：模糊/噪点/马赛克？→ 画质差
├── 美感：普通图片观感差？→ 基础美感差
└── 设计感：海报/Logo等排版/配色/字体差？→ 设计感差
```

### Step 4：专项判断硬规则

遇到以下情况，按维度强制归属：

| 情况 | 归属维度 | 说明 |
|------|---------|------|
| 水印/平台标签被去除 | 通常可接受 | prompt 明确要求保留时 → 指令遵循 |
| 文字多字/少字/错字/乱码 | 指令遵循 | 不影响原意的合理扩充不判错 |
| 文字扭曲/残缺/重影/笔画粘连 | 视觉效果 |  |
| 文字颜色/大小/粗细未满足 | 指令遵循 | prompt 未要求时不判 |
| 排版位置混乱、影响阅读 | 视觉效果-设计感差 | prompt 明确要求位置时 → 指令遵循 |
| 特殊符号（数学/emoji/希腊字母）错误 | 指令遵循或视觉效果 | 按漏响应/错误/结构崩坏判断 |
| 多指/少指/肢体连接错误/穿插粘连 | 视觉效果-结构崩坏 | 非科幻设定默认 5 指标准 |
| 悬浮/重力/反射/比例/运动异常 | 视觉效果-违反物理规律 |  |
| 拉伸/压缩导致形变 | 视觉效果 | prompt 要求画幅未满足时同时属指令遵循 |
| 编辑任务中模糊/噪点/清晰度下降 | 视觉效果-画质差 | 合理正向优化不判 |
| 未被要求改变的色调/亮度/对比度变化 | 一致性 | prompt 要求调整未完成 → 指令遵循 |

### Step 5：填分维度 GSB（每个维度独立）

```text
对每个维度：
├── 一图有明确、可具体说明的优势 → 选它更好
├── 两图都没问题 / 问题相同或相近 / 差异太轻微 → 无法区分
└── ⚠️ 指令遵循优先！图2更好看但没完成核心指令 → 指令维度图2不能判更好
```

### Step 6：选归因标签

**问题→标签映射表：**

| 你看到的问题 | 标签 |
|------------|------|
| **【指令遵循】** | |
| 专有名词/流行概念生成错了 | 世界/专业知识--新概念/流行的/专有的新名词响应错误 |
| T2I 中名人不像 | 世界/专业知识--名人不像（非给定图，仅用于 T2I） |
| 场景类型错了 | 世界/专业知识--场景类型错误 |
| 完全没做某条指令 | 指令响应--完全未响应 |
| 人脸妆容/姿势/景别/性别/服饰/表情 | 指令响应--人像相关元素响应差 |
| 动植物/道具/背景/图案/画幅比例 | 指令响应--物体/图像等具象元素响应差 |
| 风格/色彩/滤镜不对 | 指令响应--风格/色彩等抽象元素响应差 |
| 数量不对 | 指令响应--实体数量响应差 |
| 位置不对 | 指令响应--实体位置响应差 |
| 以上都不匹配（尽量别用） | 指令响应--其他内容响应差 |
| **【一致性】** | |
| 知名 IP 形象变了 | 一致性--知名IP保持差 |
| 真实人脸/身体特征变了 | 一致性--真人-人物保持差 |
| 虚拟/动画人物特征变了 | 一致性--非真实人物-人物保持差 |
| 风格/色调变了 | 一致性--风格/色调保持差 |
| 背景/道具等其他元素变了 | 一致性--其他元素保持差 |
| **【视觉效果】** | |
| 多指/少指/肢体错位/穿插粘连 | 视觉效果-存在明显的结构崩坏 |
| 悬浮/重力/反射/比例/运动异常 | 视觉效果-结构无崩坏但违反物理规律 |
| 看起来假、不真实 | 视觉效果-自然真实-生成效果不自然（假） |
| 真人场景有AI塑料感 | 视觉效果-自然真实-AI感 |
| 负面/不适内容 | 视觉效果-自然真实-负向信息带入 |
| 模糊/噪点/马赛克/清晰度下降 | 视觉效果-画质差 |
| 普通图片观感差 | 视觉效果-基础美感差 |
| 海报/Logo版式/配色/字体差 | 视觉效果-设计场景中设计感差 |

> ⚠️ 硬性规则：
> - 多选标签在单元格内**必须用英文逗号 `,` 分隔**（交付多维表格按逗号拆分选项），禁止用顿号/分号。
> - 同一事实不重复打标；同一对象有独立的不同问题可分维度。
> - 能使用具体标签时，不得用“其他”类标签兜底。
> - reason 写了明确问题但未选对应标签，视为漏标。

### Step 7：填整体 GSB

按优先级逐级判断，不要在第一步就凭感觉：

```text
1. 核心指令完成情况   → 一图完成、另一图没完成 → 完成的更好
2. 明确问题数量       → 谁的问题更少 → 谁更好
3. 问题严重程度       → 主体 > 边缘，结构崩坏 > 轻微画质差异
4. 视觉显著性         → 靠近中心/占比大 > 边缘/占比小
5. 以上都没充分差异   → 无法区分
```

> **硬性规则**：整体 GSB ≠ 分维度多数票。核心指令未完成通常比轻微美观差异更严重。

### Step 8：写 reason

**模板：**

```text
指令遵循：图1[具体对象][具体问题]；图2[具体对象][具体问题]。
一致性：图1...；图2...。（T2I写"不涉及"）
视觉效果：图1...；图2...。
综合判断：由于[关键差异]，因此[结论]。
```

**写后硬性检查：**

- [ ] 图1的显著问题都写了？（含它胜出的情况）
- [ ] 图2的显著问题都写了？（含它胜出的情况）
- [ ] 两图共性问题写了？
- [ ] 每个问题有具体对象和位置？（不能只写"有问题""效果差"）
- [ ] 没有只描述落败图的问题？
- [ ] 没有编造无法确认的轻微问题？
- [ ] 结论和 GSB/标签一致？

### Step 9：本条自检 + 疑难 case 处理

**自检清单（全部通过才能进入下一条）：**

```text
□ 整体 GSB、三个分维度 GSB、归因标签、reason 互相一致
□ T2I 任务：一致性=不涉及，一致性归因标签=空
□ prompt 写"保持XX"的问题归在指令遵循
□ 不是先选整体再反推分维度
□ 差异不够明确时选了"无法区分"
□ reason 有具体对象、具体位置、具体问题
□ 标签和 reason 严格对应
□ 没有因同一事实在两个维度重复归因
□ 没有使用"其他"类标签兜底
□ 没有复制模板未修改具体对象
```

**疑难 case 挂起：**

遇到以下情况，**不得强行标注**，必须挂起：

1. 图片无法查看且影响核心判断。
2. 规则未覆盖的场景。
3. 两图问题复杂到无法确定边界归属。
4. 任务类型无法明确判定。

**挂起动作**：
1. 将该条行号、疑点描述写入 `sessions/.../<date>/difficult-cases.xlsx`。
2. 在 reason 中写：`⚠️疑难 case：[原因]`。
3. 在 GSB 字段留空或写 `待确认`。
4. 继续标注下一条；疑难 case 待统一口径后回填并重新校验。

## 禁止事项

- ❌ 先选整体再让分维度跟从
- ❌ 强行分胜负
- ❌ prompt 写"保持XX"归入一致性
- ❌ T2I 判一致性或填一致性标签
- ❌ 按个人审美选边
- ❌ reason 不写具体对象和问题
- ❌ reason 只写落败图问题
- ❌ 用"其他内容响应差"兜底
- ❌ 同一事实多维度重复归因
- ❌ 复制模板未修改具体对象
- ❌ 使用 image1、图1、same 等非标准值
- ❌ 规则未覆盖时自行扩展口径

---

## 退回标准速查

出现以下任一情况，**整条退回**：

1. 整体或任一分维度结论错误。
2. 指令遵循与一致性边界判错。
3. 应判“无法区分”却无依据硬选边。
4. 归因标签漏选、错选或重复归因。
5. reason 漏掉任一方的显著问题或两图共性问题。
6. 只描述落败图、没有客观说明胜出图问题。
7. 问题描述笼统，未写具体对象或位置。
8. reason 模板化、与字段或最终结论矛盾。
9. T2I 错判一致性。
10. 触发 AI 感豁免却仍标 AI 感。
11. 使用非交付标准值。
