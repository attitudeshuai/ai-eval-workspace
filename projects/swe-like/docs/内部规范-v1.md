# 内部规范

## Commit URL 填写要求

在使用 TRAE CN进行跑题之前，需要把目标Repo fork一份。然后克隆这个自己的Repo然后跑模型。模型跑完后需要将代码修改变成一个单独commit然后push到GitHub。复制这个commit URL 到提交表格。\(**commit 务必只能包含模型修改的部分**）

这么做的目的是为了记录一下模型的修改记录，同时这个fork 仓库也是模型的修改环境。

## TRAE CN 积分

使用文档要求使用 SeedEvolving 模型，需要开通 Pro 会员。新账号开通 Pro 会员可以省 30 元，同时还会赠送 2500 积分。

因此，每个账号用完 Pro 会员的 4000 积分和新账号赠送的 2500 积分后，可以使用一个新手机号注册新账号，然后重新购买会员。

需要注意以下几点：

- 同一台电脑登录多个账号存在风控风险。同一台电脑使用完两个账号的积分后，需要使用 Codex 清除 TRAE CN 的所有安装痕迹，然后重新安装 TRAE CN。

- 新账号购买 TRAE CN Pro 会员，首月为 59 元订阅付费。大家付费完成后，记得在微信或支付宝中取消订阅，然后顺手去「订阅管理」中把发票开了。

## 表单数据填写规范

- 表单中的任何字段都不允许包含 Markdown 标签，尤其是标题、引用、代码块、加粗、斜体等。否则一看就是 AI 生成的。填写的内容不能有明显的 AI 味。

- 为了体现数据真实性，type 字段 = 有效轮数 \< 100 且效果好的数据，其数量需要大于等于总提交数量的 25%。（有效轮数 \< 100 且效果好的数据不结算）

- 本轮 100 题的语言仅限 Go / Python。

- 严禁从 GitHub Issues 中照抄需求。有 AI 质检，会自动打回。

- 一个 Repo 最多提交 5 条数据。

- Prompt 要像这个 Merge Request 开发前真实收到的需求。Merge Request 改了什么就写什么，不要额外扩展成一份「大而全」的需求文档。

- **最最最最最最最重要的是：出的题要和 Repo 匹配，是该 Repo 的管理员可能会合并到主分支的需求。**



## TRAE 省积分经验

- 执行超过两个小时的任务就可以停止，然后按照「\> 100 轮且效果差」提交数据。

甲方希望尽可能提交完整数据，未完成的数据越少越好。如果到一个半小时时，模型正在跑测试或执行任务，而不是反复思考、输出异常，或者看起来马上就要结束了，可以再等等，尽量提交完整数据。

此要求主要是为了给每道题设置一个积分消耗上限。

- 不要为了节约积分，故意出很难或者不合理的题。我们本轮 100 题的目的是拿下这个长期项目。
