# 常见问题

1. **题目和 repo 中的 issues 重复或相似（预检打回率最高的原因）**
   - 解决：出题时和历史 issues 语义+功能上去重、去相似；**open 和 closed 都查**（closed 也算重复）；同义词/中英文多搜几轮；查重证据（搜索词 + 命中 issue 编号 + 排除理由）记入 task.toml 的 notes

2. **题目太简单（预检打回）**
   - 现象：单文件改动、纯配置开关、对现有能力的薄封装 → 有效轮数必然 <100，也没有训练价值
   - 解决：定稿前按 `skills/01-task-create.md` 的「难度门槛自检清单」自检，至少命中 3 项（跨模块 / 状态生命周期 / 并发竞态 / 配置面 / 边界失败路径 / 向后兼容）

3. **功能在 base_commit 处其实已实现（「已有功能」型打回）**
   - 原因：base_commit 较新，凭印象出题——很多「明显缺口」上游已经补了（如 caddy 的日志 sampling、map 正则、browse 自定义模板）
   - 解决：先在本地仓库 grep 验证功能不存在（含相近命名、相近能力的变体），再写题

4. **轮次太少**
   - 解决：提高任务难度（见第 2 条）

5. **部分字段出现一眼模板化的内容**
   - 解决：调整字段生成规则；realism_and_difficulty 等字段按本题实际写，不套模板句式
